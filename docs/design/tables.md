# Tables

How the spreadsheet area behaves. The parts and rules it builds on live in [DESIGN.md](../../DESIGN.md).

A workbook (`src/app/(app)/tables`) is a spreadsheet and the densest surface in the app. The tables browser is an ordinary list page: New folder, New from file and New workbook (the filled one) in `PageHeader`, and a search that filters as you type in `ListToolbar`. A workbook page fills the viewport height (`h-svh`): `PageHeader` with the workbook name and Tables as the back step, a strip of table tabs, then the active table.

- **Names.** On the workbook page, the workbook name and each table tab rename in place. The title is an `EditableTitle` (`PageHeader`'s `rename`): hover or focus shows a muted ground and a pencil, a click, Enter or F2 opens the field, Enter or leaving it saves and Escape cancels. A tab opens the same field on a double-click, F2 or Rename in its menu, and a new table opens with its tab in rename under the default name. No dialog names a table or renames a workbook there. The tables browser is a list of many workbooks and folders, so its row menu renames one through a name dialog. The header's actions area holds one ghost More menu with Move to folder and Delete workbook.
- **Tabs.** The strip is a `ScrollCue` without a hint line, with New table after it. The open tab shows its More menu; the others show it on hover or focus, and a touch screen offers it on the open tab only. On a phone the tabs, the menus and New table are 44px tall. The table stacks its toolbar, the filter and sort chips, the selection bar and the grid at `gap-2` inside `p-3`, tighter than the page roles, because the grid needs the room.

- **Editors.** A cell edits in place. A select column opens the app's `Select` on the cell: a pick commits, and Escape, Tab or a click outside discards. A date column types yyyy-MM-dd in the cell with a `Calendar` under it; a click on a day commits it, and the keys stay those of a text cell.
- **Grid.** `DataGrid` is one `role="grid"` scroll container with a hairline border and rounded-lg. Rows are 32px and the header 36px on a muted band. A 72px gutter holds the row checkbox and number. The scroller is `isolate`, so the grid's layers stay inside it: the header row on top (z-30), then the gutter and pinned columns (z-20), then the active cell (z-10). A boolean cell shows a check icon. Cells are text-sm. The header names the column at text-xs medium, with the type and the fill rate in text-xs muted text; the fill rate opens a tooltip with the percentage in words. Numbers and currency align right in tabular numerals. Formula columns and columns a run fills are read-only and sit on a `bg-muted/30` tint. Pinned columns stay on the left behind a shadow edge; at phone width the grid ignores pins. The grid renders the rows in view and loads more near the end.
- **Toolbar.** Two groups. On the left, what you see: search, Filter, Sort, Columns and the row count. On the right, what you do, in the order the work goes and ending on the one filled button: Undo and Redo (ghost, left out on a phone, where the grid's keys do the work), Add (columns, then rows and Import file), Push to campaign paired with an Export CSV icon button (the two ways rows leave the table), Enrich, then Run. Enrich is a menu of the four outcomes, Ask AI about each row and All enrichments; it is filled until the table has a column that runs, and then Run takes the fill and stays last, so the filled button never moves inside the row. Push and Export, and Run with its options chevron, are `ButtonGroup`s; "Auto-run on" shows in Run's chevron while the table auto-runs. On a phone the left group takes the first line and the right group's secondary buttons show their icons; counts stay visible.
- **Enrichment start.** A table with rows and no running column shows one hairline-ruled line of text-xs under the toolbar: "Enrich these rows:", the four outcomes and Ask AI about each row as underlined links into the same choices as the Enrich menu, and "Nothing runs or spends until you press Run". It has no box and no buttons, so the toolbar keeps the one filled button. It goes once a column runs.
- **Enrichment dialog.** It opens on four outcome tiles (`CHOICE_TILE`: Find work emails, Verify emails, Enrich people, Enrich companies), or on one outcome straight from the Enrich menu, where Cancel replaces Back. An outcome reads as three ruled lines, each a label, a sentence and a Change link that opens its fields: Provider (the vendor and its price a lookup; a second tick tries providers in order, "Hunter, then ZeroBounce"), Match rows on (the mapped inputs, the columns they come from and how many rows have them; each input shows its column's first value, and the fields stay open while the mapping covers nothing) and Adds (the new columns as chips, ticked from what the outcome names, with the column name behind Edit). Options folds the caps, timing and reuse. Until a connected provider offers the outcome, the dialog lists only the vendors that do, each connecting in place with its key and price, and keeps what you set. The footer says what a full run can cost, or why the add buttons are off; "Add column" is the filled button and "Add and run first 10 rows" the outline one, so nothing spends until you choose to.
- **One enrichment, one column.** The enrichment column shows the action's main answer and is named for it (Work email, Email status). Other fields become columns only when ticked, or later from the cell drawer's More fields. An empty cell whose row lacks an input reads "Needs email" in muted text.
- **Selection.** The active cell takes a 2px primary ring, a range a `bg-primary/10` tint and a selected row `bg-primary/5`. The tints come from primary, so they stay grey. The fill handle at the corner of a range copies it down on drag. Selected rows open the shell's `BulkBar` above the grid, in the flow (`sticky={false}`): "{n} selected.", "Select all {N} matching rows", then Run, Push to campaign, Export, Delete and Clear selection, all outline or ghost; red waits for the confirm step. With nothing selected the bar takes no room.
- **Keyboard.** Arrows, Page Up and Down, Home and End move; Ctrl or Cmd jumps, Shift extends the range. Tab moves across and leaves the grid at the first or last cell. Enter or F2 edits, and a typed character starts an edit with it. Delete clears the range, Shift+Space selects the row, Ctrl or Cmd+A selects every cell, Ctrl or Cmd+Enter runs the cell, Alt+Enter opens the cell drawer and Escape clears the row selection. Copy, cut and paste carry tab-separated text. Ctrl or Cmd+Z undoes and Shift+Z or Y redoes while the grid has focus. Table tabs move with the arrow keys and reorder with Alt+Arrow or a drag. A column's resize handle takes focus: Left and Right resize by 10px (50px with Shift), Home and End jump to the narrowest and widest.
- **Cell states.** A cell shows one trailing icon at most: a spinner while it runs, a red alert for an error, an amber alert for a skipped cell and an amber refresh icon for a stale one. The reason sits in screen-reader text the cell points to (`aria-describedby`), and in a tooltip on the active cell only, so the grid mounts one tooltip at most. "This table changed elsewhere." takes the amber icon and a Reload button. Run progress is a bordered status line with a thin primary bar, the counts, Stop and Retry failed.
- **Cell drawer.** `CellDrawer` is a right `Sheet`, full width on a phone and `sm:max-w-lg` from sm up (the width classes carry the `data-[side=right]:` prefix so they replace the Sheet's). The column name is the title and "Row n · type" sits under it. Three sections follow with subsection heads, like the record panels: Value in a muted block with Run this cell beside its head, Last run (the error in red as a sentence, then a `dl`) and Run history as a ruled list, each failed run with its reason. A history that does not load shows `ErrorState` inline with Try again.
- **Column dialogs.** Add offers Column and Formula; enrichment and AI columns start from Enrich. The formula dialog previews the expression on one row. The AI dialog takes a prompt that reads other columns as `{{key}}` and makes one column per output field. The enrichment dialog runs one provider action, or several tried in order. The run dialog picks rows with a `RadioGroup`. These and the run dialog are plain `Dialog`s at `sm:max-w-2xl`, capped at 90 to 92svh with a scrolling body. Their fields use the Field family, like every form.
- **Filter and Sort.** Two `ToolbarPopover`s (see Filters and sorts in [DESIGN.md](../../DESIGN.md#filters-and-sorts)). Filter holds the condition builder at the `builder` width: column, operator, value, mute and remove per condition, groups nested up to the view's depth, and Match all or any. Sort lists the sorts in order with Add sort. Each edits a draft and saves the view once on Apply, so a half-typed value never reaches the server. A muted condition stays in the view and filters nothing, and the Filter count leaves it out. `AppliedFilters` shows the conditions and sorts above the grid, with Match all or any beside them. A member looking at their own view gets a muted line with Reset to default view.
- **Conflicts.** When another person or a run changed rows you edited, `ConflictDialog` saves nothing and lists each cell with Now and Yours (yours at medium weight). The footer offers Keep current values and Retry my edits.
- **Empty and loading.** An empty table shows `EmptyState` with Import file and Add rows; a search or filter with no hits shows "No rows match". Loading shows skeleton bars. A failed load shows `ErrorState` with Try again.
